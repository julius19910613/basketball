## 🔍 二、竞品研究关键发现

### 值得借鉴的设计模式

| 参考来源 | 核心借鉴点 |
|---------|-----------|
| **B-Ball Scoreboard**（iOS）| 一键计分，超大触控目标，场上快速操作 |
| **ScoreKeeper**（iPad）| 多场比赛并行计分，高对比显示，适合围观 |
| **Fastbreak Compete** | 完整赛事平台，AI 分组，实时比分推送 |
| **Tournify** | 分 step-by-step 引导创建赛事，模板复用 |
| **bracketeer**（开源）| 循环赛/淘汰赛算法，可直接集成 |
| **brackets-manager.js** | 通用赛事管理逻辑，开源可复用 |
| **斑马邦**（国内）| 俱乐部运营、约球、社交，成熟变现路径 |

### 通用 UX 原则

1. **场上计分优先移动端**：单手操作，大按钮，容错设计
2. **草稿机制**：创建流程支持中途保存，不丢失数据
3. **实时同步**：比分变化有动画反馈，队员可围观
4. **数据可视化**：球员统计用雷达图/柱状图，不用纯数字
5. **分享即增长**：战报图片生成是核心传播手段

## 🎯 三、下一阶段功能设计（Phase 2 → Phase 3）

### P2-1：战绩筛选 + 比赛排序（快速修复）

**问题**：比赛列表只能按草稿/完成筛选，无法快速查看胜负情况。

**交互设计**：

```
比赛列表 TabBar：
[全部] [草稿] [已完成]
         ↓ 扩展为
[全部] [胜] [负] [平] [草稿]

Card 展示优化：
├─ 比赛日期 + 对手名称
├─ 比分大字显示（醒目）
├─ 胜负标签（绿胜/红负/灰平）
└─ 箭头指示 → 进入详情
```

**实现成本**：低（修改 match/list 页面 + 数据库 query 调整）

### P2-3：比赛计分页（核心交互重构）

**背景**：当前创建比赛需要手动输入所有数据，场上使用极其不便。参考 **B-Ball Scoreboard** 设计实时计分页。

**页面路径**：`/pages/match/score/score`（新页面，替代手动创建流程）

**交互设计 — 两种模式**：

#### 模式 A：快速计分（场上使用）
```
┌─────────────────────────────┐
│  ⏱️ 12:00  |  第1节  |  🔔  │
├──────────────┬──────────────┤
│   🏀 湖人     │    勇士 🏀    │
│              │              │
│    [ 86 ]    │    [ 92 ]   │  ← 超大字号，一键+分
│              │              │
│  [+3] [+2]   │  [+3] [+2]  │  ← 大按钮，减小误触
│  [+1] [-1]   │  [+1] [-1]  │  ← 容错设计
├──────────────┴──────────────┤
│  [第1节][第2节][第3节][第4节] │  ← 节数切换
│  22:18  24:22  18:28  22:24 │  ← 每节小计
├─────────────────────────────┤
│  [保存草稿]      [结束比赛]  │
└─────────────────────────────┘
```

**关键 UX**：
- 按钮 88rpx × 88rpx，间距足够，单手操作
- 比分变化有缩放动画反馈
- 场上切节数时自动保存到本地（`wx.setStorage`），防丢
- 结束后一键生成战报图片

#### 模式 B：详细数据录入（赛后补录）
```
┌─────────────────────────────┐
│  比赛详情  ·  数据录入       │
├─────────────────────────────┤
│  👥 参赛球员（已选 10 人）    │
│  [添加/移除球员]             │
├─────────────────────────────┤
│  📋 球员数据表格             │
│  姓名  得分  篮板  助攻 ...  │
│  张三   18     8     4   [+ ]│
│  李四   12     3     6   [+ ]│
│  ...                        │
└─────────────────────────────┘
```

### P2-4：战报图片生成（社交传播）

**页面路径**：比赛详情页底部新增「分享战报」按钮

**技术方案**：使用 `wx.createCanvasContext` 绘制图片

**战报模板**：
```
┌─────────────────────────────┐
│  🏀 篮球战报                 │
│  湖人 vs 勇士               │
│                             │
│  🏆 86 - 92                 │
│  胜                            │
│                             │
│  📅 2026.04.28 14:00        │
│  📍 室内篮球馆               │
│                             │
│  ── 球员数据 ──             │
│  张三  18分 8篮板 4助攻     │
│  李四  12分 3篮板 6助攻     │
│                             │
│  ⚡ 来源：篮球小程序         │
```

**交互**：点击 → 绘制 Canvas → 显示预览 → 用户确认后调用 `wx.saveImageToPhotosAlbum` 或直接 `wx.shareImageToFriends`

### P2-5：订阅消息通知（队员通知）

**触发场景**：
- 比赛创建后 → 通知队员「有新比赛待确认」
- 比赛结束后 → 通知全队「战报已生成」
- 球员绑定成功/失败 → 通知用户

**实现要点**：
- `wx.requestSubscribeMessage` 在**用户点击时同步调用**（见 AGENTS.md ⚠️）
- 模板消息存数据库，不实时推送（微信限制）
- 建议优先接入「订阅消息通知」云调用

## 📐 五、交互规范补充

### 按钮尺寸（场上计分场景）
```
主要按钮（+分）：  88rpx × 88rpx，min 72rpx
次要按钮（-分）：  60rpx × 60rpx
文字按钮：        高度 80rpx，padding 0 32rpx
```

### 动画反馈
```
比分变化：  scale(1.2) → scale(1)，300ms ease-out
Tab 切换：  下划线滑动，200ms
Card 按压：  opacity 0.7，100ms
保存成功：  绿色对勾 + fadeOut，500ms
```

### 空状态设计
```
无比赛：  🏀 暂无比赛记录
         [创建第一场比赛]

无球员：  👥 还没有球员
         [添加球员] 或 [批量导入]

无数据：  📊 暂无统计数据
         完成比赛后会显示
```

### 错误处理
```
网络失败：  显示红色提示条，3s 自动消失
数据为空：  展示空状态引导页
权限不足：  弹出授权引导
```
